# Image-to-Code Skill

Generate premium website design references, analyze them deeply, then implement faithful frontend.

---

## CORE DIRECTIVE: IMAGE-FIRST WORKFLOW

For visual website tasks, this order is mandatory:

1. **Image generation first** — generate design image(s) yourself
2. **Deep image analysis second** — extract text, typography, spacing, colors, layout, buttons, component logic
3. **Implementation third** — build frontend to match the generated design as closely as possible

Do not skip image generation when available. Do not begin with freeform coding. The generated image(s) are the primary visual source of truth.

## 2. MANDATORY IMAGE-FIRST RULE

For website design requests where visual quality matters:

1. Generate the design image or image set yourself first
2. Deeply inspect and analyze the generated image(s)
3. Extract the design system from them
4. Implement the frontend only after that

Do not start with freeform coding. The image is the design source. The code is the translation layer.

---

## 3. SECTION IMAGE RULE

Generate one separate image per section. Always.

- 1 section → 1 image
- 4 sections → 4 images
- 8 sections → 8 images
- 12 sections → 12 images

Do not compress multiple sections into one image. Text stays readable, typography becomes analyzable, spacing stays visible, extraction quality improves.

---

## 4. FRESH GENERATION RULE

When a section needs a dedicated image, generate a fresh new image. Do not crop from previously generated larger images. Cropped images destroy spacing accuracy, type scale relationships, and layout proportions.

If a section is not clear enough, regenerate it as a new standalone image with the same visual language but cleaner, more analyzable rendering.

---

## 5. DEEP IMAGE ANALYSIS

Before implementing, deeply analyze every generated image:

- Exact visible text (hero headline, subheadline, CTA, section titles)
- Typography character (size relationships, weight, line count, tracking, serif vs sans)
- Spacing relationships (section gaps, card padding, image-to-text distance)
- Button analysis (size, shape, radius, fill vs outline, hierarchy)
- Color palette (background, accent, text hierarchy, shadows)
- Layout structure (grid logic, section ordering, visual rhythm)

If something is unclear, generate another image before coding.

## 7. HERO MINIMALISM RULES

- Hero must feel like a strong opening scene
- Keep hero composition very clean
- Do not overcrowd the first viewport
- Main headline: 1-3 lines maximum
- Keep supporting text concise
- Prioritize negative space and contrast
- Avoid stuffing with pills, fake stats, badges, tiny logos

### Hero Cleanliness Rule
- Use a strong single focal point
- Keep the hierarchy obvious
- Let the hero breathe
- Keep the first screen readable on a smaller desktop viewport

---

## 8. ANTI-AI-SLOP RULES

### Layout slop
- One giant unreadable collage
- Endless centered sections
- Identical card rows repeated section after section
- Cards-inside-cards-inside-cards
- Giant rounded section containers wrapping everything

### Visual slop
- Default purple/blue AI gradients
- Too many glowing edges
- Floating blobs everywhere
- Glassmorphism stacked without reason

### Typography slop
- Giant heading + weak tiny subcopy
- Too many font moods
- Awkward line breaks
- Lazy all-caps everywhere
- Generic gradient headline tricks

### Content slop
- "Unleash", "Elevate", "Revolutionize", "Next-Gen", "Seamless"
- "Acme", "Nexus", "Flowbit", "Quantumly", "NovaCore"
- Pseudo-enterprise control labels
- Decorative system markers

---

## 9. DESIGN-TO-CODE COPY DISCIPLINE

After generating and analyzing the reference image(s), implement the website faithfully:

- Follow the references closely
- Preserve layout logic, spacing rhythm, section ordering
- Preserve text/image balance, typography mood, component style
- Do not drift into a different design direction
- Do not "improve" the design by replacing it with a generic coded layout

The goal is visually faithful to the image, translated into real frontend.

---

## 10. MISSING DETAIL RESOLUTION

When implementing from images, some details may be unclear. Resolve by:

1. Preserve the visible design language
2. Preserve layout and spacing logic
3. Preserve component family
4. Preserve mood and polish level
5. Generate an extra detail image if needed
6. Only then choose the most implementation-friendly faithful version

## 12. CLARITY CHECK

Before finalizing, verify:

1. Has the design been generated first?
2. Have all generated images been deeply analyzed?
3. Is the text readable enough?
4. If not, were extra detail images created?
5. Were enough images generated?
6. Were unclear sections regenerated as fresh standalone images?
7. Is the hierarchy obvious?
8. Is the hero clean enough?
9. Is typography analyzed properly?
10. Are spacing relationships understood?
11. Are buttons and components extracted properly?
12. Are colors analyzed properly?
13. Is the design visually distinctive?
14. Is it free of obvious AI tells?
15. Can someone code from this faithfully?
16. Have unnecessary nested boxing been removed?
17. Is the first screen clean and readable on a small laptop?
18. Have useless pills, labels, and fake technical micro-elements been reduced?
